# 🏓 Пинг-понг: турнир + тотализатор

Telegram Mini App для турнира по настольному теннису на 8 человек со встроенным
пулом-тотализатором. Всё считается на клиенте, бэкенда нет — состояние живёт в
`localStorage`.

- **Стек:** React 18 + TypeScript + Vite, Tailwind CSS, `@telegram-apps/sdk-react`.
- **Формат:** 2 группы по 4, круговая до 2 побед в партиях (партии до 11, при 10:10 —
  разница в 2), плей-офф крест-накрест до 3 побед.
- **Тотализатор:** банк ровно **800 ₽** (8×100). Кэфы — множители **очков**, не рублей.
  Доля в банке = очки игрока ÷ сумма всех очков × 800 ₽.

Экраны: Главная · Группы · Сетка · Ставки · Раскрытие ставок · Итоги (лидерборд) ·
Админка (скрытый вход — **долгий тап по заголовку**).

## Быстрый старт

```bash
npm install
npm run dev        # http://localhost:5173/pingpong-tournament/
npm test           # юнит-тесты (тайбрейки + сходимость банка в 800)
npm run build      # проверка типов (tsc) + продакшн-сборка в dist/
npm run preview    # локальный предпросмотр собранного билда
```

Требуется Node ≥ 18 (проверялось на Node 20/24).

### Как «прогнать» весь турнир
1. Пока линия открыта — на экране **Ставки** каждый выбирает себя, раскидывает
   100 очков и сохраняет. Телефон идёт по кругу (чужие ставки скрыты).
2. Долгий тап по заголовку → **Админка** → «Закрыть линию и раскрыть ставки».
   Это ключевой момент: все ставки раскрываются разом.
3. Вводите счета матчей (Главная → «Ввести счёт» или Админка). Таблицы, сетка,
   выходящие, бонусы и выплаты пересчитываются сами.
4. Экран **Итоги** — лидерборд по очкам и рублям; строка «последнее место покупает мячи».

## Деплой на GitHub Pages

Проект — статический SPA, любой хостинг подойдёт. Для GitHub Pages важен **base
path**: сайт живёт по адресу `https://<user>.github.io/<repo>/`, поэтому ассеты
грузятся из подпапки `/<repo>/`.

Base path берётся из переменной `BASE_PATH` (см. `vite.config.ts`), по умолчанию
`/pingpong-tournament/`. Если репозиторий назван иначе — либо переименуйте, либо
задайте `BASE_PATH` при сборке.

### Вариант A — GitHub Actions (рекомендуется)
В репозитории уже есть `.github/workflows/deploy.yml`, который на каждый push в
`main` гоняет тесты, собирает билд с правильным `BASE_PATH` и публикует Pages.

1. Создайте репозиторий на GitHub и запушьте код в ветку `main`.
2. **Settings → Pages → Build and deployment → Source = GitHub Actions**.
3. Дождитесь зелёного workflow. Сайт: `https://<user>.github.io/<repo>/`.

Workflow сам подставляет `BASE_PATH=/<имя-репозитория>/`, так что переименование
репозитория ничего не ломает.

### Вариант B — вручную
```bash
BASE_PATH=/<repo>/ npm run build      # Windows PowerShell: $env:BASE_PATH='/<repo>/'; npm run build
npx gh-pages -d dist                  # опубликовать содержимое dist/ в ветку gh-pages
```
Затем **Settings → Pages → Source = Deploy from a branch → gh-pages / (root)**.

> Роутинг внутри приложения — не по URL, а по внутреннему состоянию, поэтому 404 на
> вложенных путях не бывает и отдельный `404.html` не нужен.

## Подключение как Mini App через @BotFather

Нужен публичный **HTTPS**-URL (GitHub Pages его даёт).

1. Откройте [@BotFather](https://t.me/BotFather).
2. Создайте бота (`/newbot`) или возьмите существующего — получите токен.
3. Привяжите Mini App к боту:
   - `/newapp` → выберите бота → заполните название, короткое описание, картинку
     (640×360) и иконку → **Web App URL** = ваш адрес Pages
     (`https://<user>.github.io/<repo>/`) → задайте short name.
   - BotFather вернёт прямую ссылку вида `https://t.me/<bot>/<shortname>` —
     по ней Mini App открывается сразу.
4. (Опционально) повесьте приложение на кнопку меню бота:
   - `/setmenubutton` → выберите бота → отправьте тот же URL и текст кнопки
     (например, «🏓 Турнир»). Теперь приложение открывается кнопкой в чате с ботом.
5. Откройте бота в Telegram, нажмите кнопку/ссылку — Mini App запустится с темой,
   вьюпортом, MainButton и хаптиком.

> Приложение полностью работает и вне Telegram (обычный браузер) — Telegram-функции
> включаются автоматически, когда они доступны, иначе тихо отключаются.

## Структура

```
src/
  data/            участники, расписание, ЛИНИЯ (odds.ts), константы (rules.ts)
  logic/           чистые функции + тесты:
    setScore.ts       разбор партий/матча
    standings.ts      таблицы групп и ТАЙБРЕЙКИ  (+ standings.test.ts)
    bracket.ts        сетка плей-офф
    finalStandings.ts итоговые места 1..8
    outcomes.ts       резолв каждого исхода линии (+ outcomes.test.ts)
    bonus.ts          бонусные очки за результат (+ bonus.test.ts)
    payout.ts         выплаты, сходимость в 800 ₽ (+ payout.test.ts)
    tournament.ts     сборка производной модели (buildView)
  storage/         репозиторий: интерфейс + реализация на localStorage
  state/           React-контекст (единственный источник действий/состояния)
  telegram/        адаптер к @telegram-apps/sdk-react (с фолбэками)
  components/ screens/   UI
```

### Замена localStorage на API
Весь UI обращается только к интерфейсу `TournamentRepository`
(`src/storage/repository.ts`) — методы `load/save/clear` уже асинхронные. Чтобы
переехать на бэкенд, достаточно написать новый класс (HTTP/WebSocket), реализующий
этот интерфейс, и подставить его в `src/storage/index.ts`. Экраны и логика не
меняются.

Формат хранения — минимальный «источник правды» (только введённые счета, ставки и
статус линии) под ключом `pingpong-tournament-v1`; всё остальное (таблицы, сетка,
выплаты) выводится чистыми функциями.
